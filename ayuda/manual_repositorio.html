📖 1. Descripción General

La Red Sísmica de Alerta (RSA) es una infraestructura enfocada en el análisis sismológico y la instrumentación en tiempo real. Este repositorio almacena herramientas críticas para el procesamiento de trazas sísmicas en formato MiniSEED/EVT, el cálculo automatizado de caudales de filtración, la generación de reportes diarios/acumulados, y utilidades de configuración de hardware (microcontroladores ESP32).

Tecnologías Core

Python 3 🐍
Lenguaje core del proyecto, utilizando paquetes científicos y de análisis de datos estructurados.
PyQt5 🖥️
Librería de GUI que permite a los operadores interactuar visualmente con los sismogramas y gráficos.
ObsPy 🌋
Librería sismológica específica para leer, escribir y procesar formatos MiniSEED, SAC y eventos sísmicos.

📂 2. Arquitectura de Directorios

El código fuente se distribuye en carpetas lógicas para mantener una separación clara entre la interfaz de usuario, las librerías científicas, y los programas del sistema:

src/ Core
Contiene el punto de entrada principal del sistema integrado (`programa_integrado.py`), las carpetas de interfaz gráfica (`gui/`, `ui/`), subprogramas específicos y librerías transversales.
modulos externos/ Scripts
Scripts independientes para tareas auxiliares: inserción manual/automática de estaciones, cálculo de caudales de filtraciones, acelerógrafo y reporte diario.
esp_32/ Firmware
Código y librerías en MicroPython para los microcontroladores que monitorean instrumentación remota y sensores ADC, HX711, AHT20, etc.
pruebas/ Sandbox
Scripts de prueba históricos, utilidades para graficar datos crudos y consultas sísmicas de prueba.

🤖 4. Directivas de Agentes (Codex & Antigravity)

Se ha creado un archivo global unificado en la raíz del proyecto para gobernar las modificaciones automáticas del agente:

⚠️ Regla de Oro
Nunca comiences un cambio sin antes haber abierto y analizado el _contx.md del archivo que vas a modificar. Esto previene alterar variables críticas como nombres de widgets (PyQt5) y firmas de funciones internas.
  • No renombrar interfaces (UI): Los nombres de objetos de PyQt5 (`self.btn_graficar`, `self.tabla_eventos`, etc.) no deben modificarse bajo ningún motivo.
  • Preservación de estructuras JSON: Los esquemas de configuración de estaciones y fases no deben cambiarse para no dañar los scripts existentes.
  • Compatibilidad de Rutas: Evitar barras diagonales codificadas a mano. Usar siempre `os.path.join` o `pathlib.Path` para asegurar que el código funcione tanto en entornos de desarrollo de Windows como en servidores.
  • Traducciones idiomáticas prohibidas: Respeta el idioma establecido en cada archivo (español o inglés). No intentes "corregir" o traducir nombres de variables ya declaradas.
  • Control de Commits (Regla GENERA COMMIT): El agente no realizará commits de manera automática. Solo agrupará y confirmará los cambios en un commit integral y contextualizado cuando el usuario escriba explícitamente la frase clave GENERA COMMIT.

⚡ 5. Ejecución de Tareas y Scripts

El repositorio está diseñado para una depuración y ejecución ágil en Spyder o mediante scripts de procesamiento por lotes en Windows:

Lanzadores por lotes (.bat)

En el directorio raíz existen archivos ejecutables en lote (`.bat`) para tareas automatizadas rápidas:

  • Spyder.bat: Configura el entorno e inicia el IDE Spyder cargando el proyecto.
  • Programa principal.bat: Lanza la aplicación de escritorio principal (`programa_integrado.py`).
  • Acelerografos.bat: Corre la descarga y procesamiento automático del acelerógrafo.
  • Reporte diario.bat: Ejecuta el generador de reportes del día actual.
Ejecución Manual de Auditoría

Puedes verificar la calidad del código, diagramas de flujo y consistencia de librerías corriendo los scripts auditores en la terminal:
